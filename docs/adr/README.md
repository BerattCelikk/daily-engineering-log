## Format Specification
Each record adheres to the lightweight MADR (Markdown Architectural Decision Records) structure:
1. **Title & Status:** Proposed, Accepted, Deprecated, Superseded
2. **Context & Problem Statement:** Why is this decision required?
3. **Decision Drivers:** Constraints and business/technical requirements
4. **Considered Options:** Alternatives evaluated
5. **Decision Outcome:** Chosen solution with architectural justification
6. **Consequences:** Positive, negative, and operational trade-offs
